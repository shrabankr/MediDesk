# ADR-021: LAN / Multi-Computer Mode Architecture

## Status
Accepted

## Context
MediDesk was originally developed as an offline-first, single-desktop healthcare and pharmacy management system. In multi-room clinics and retail medical stores, multiple workstations (Owner PC, Doctor Consultation Rooms, Reception/Queue Desk, and Pharmacy POS Counters) must work concurrently on the same organization database with zero or intermittent Internet connectivity.

Traditional approaches often resort to placing the SQLite database file on a shared Windows SMB/CIFS network share or exposing SQLite over network drive mappings. This approach is prone to database corruption, broken file locks, race conditions, negative inventory stocks, and security vulnerabilities.

## Decision
1. **Hub-and-Spoke Topology with Authoritative LAN Server:**
   - One designated workstation operates as the **MediDesk LAN Server** (`LAN_SERVER` mode).
   - Only the LAN Server process directly accesses the SQLite database via `better-sqlite3` in WAL mode.
   - Client workstations (`LAN_CLIENT` mode) never access SQLite directly; all queries and commands travel across a secure embedded HTTPS/WSS API.
2. **Zero-Trust LAN Security:**
   - The local network is assumed to be untrusted.
   - Workstation pairing requires a 6-digit cryptographic PIN generated by the Owner on the Server PC.
   - Owner explicitly reviews and approves each client device.
   - Requests require signed HMAC device tokens, timestamps ($\pm 300\text{s}$), nonces (replay protection), and session tokens.
   - Instant device revocation is supported.
3. **Serialized Mutex Concurrency & Zero Negative Stock Invariant:**
   - High-concurrency operations (such as POS sales against the same inventory batch) execute inside serialized `BEGIN IMMEDIATE` transactions on the server.
   - If stock is insufficient, the second transaction is rejected with an `InsufficientStockError`, guaranteeing zero negative stock and 100% ledger consistency.
4. **Authoritative Server Backup:**
   - Hybrid Backup (AES-256-GCM + Google Drive) runs strictly on the Server PC. Clients do not upload independent database copies.

## Consequences
- **Positive:**
  - 100% protection against SQLite network share corruption.
  - Complete zero-trust security on local Wi-Fi / Ethernet networks.
  - Zero negative inventory stock and race conditions during simultaneous sales.
  - Full single-PC standalone backwards compatibility.
- **Negative:**
  - The LAN Server PC must remain powered on and connected for client workstations to operate.
