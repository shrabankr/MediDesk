## 2. Security Domain Audit Details

### A. Electron Process Isolation & Renderer Hardening
- **Context Isolation:** Active (`contextIsolation: true`) on all `BrowserWindow` instances.
- **Node Integration:** Disabled (`nodeIntegration: false`).
- **Process Sandboxing:** Enabled (`sandbox: true`).
- **Web Security:** Enforced (`webSecurity: true`, `allowRunningInsecureContent: false`).
- **Navigation & External Links:** External URL navigation is intercepted and blocked via `setWindowOpenHandler(() => ({ action: 'deny' }))` and `will-navigate` event filtering.
- **Content Security Policy (CSP):** Strict CSP headers block inline executable scripts from unauthorized sources and disallow remote external script loading.

### B. IPC Validation & Sanitization
- **Zod Schema Gate:** Every IPC channel in `apps/desktop/src/main/ipc/` validates incoming parameters using Zod schemas from `@medidesk/validation` before executing application logic.
- **Response Envelopes:** Returns uniform `IPCResponse<T>` envelopes (`{ success: boolean, data?: T, error?: { code, message } }`).
- **Stack Trace Stripping:** Internal database file paths, raw SQL query syntax, and Node.js stack traces are stripped in production via `ErrorSanitizer`.
- **Prohibited IPC Channels:** Verified that zero generic SQL (`rawSql`, `executeSQL`) or shell command execution (`exec`, `spawn`, `runCommand`) IPC handlers exist in the repository.

### C. Role-Based Access Control (RBAC) & Developer Isolation
- **Domain-Enforced Authorization:** All permissions are validated domain-side via `RBACEngine.assertPermission(actor, permission)`.
- **Developer Privilege Denial:** The Developer role is permanently denied 42 granular permissions covering patient records, clinical consultation notes, electronic prescriptions, pharmacy inventory, POS sales, and disaster restore operations.
- **No Universal Backdoor:** Verified that no `SUPER_ADMIN` or master bypass role exists in the authentication subsystem.
- **Last-Active-Owner Invariant:** The database and application service strictly prohibit deleting, deactivating, or demoting the last active Owner account.

### D. Zero-Trust LAN Transport & Pairing Security
- **Transport Encryption:** All multi-workstation traffic is encrypted over TLS 1.3 with dynamically generated self-signed certificates and pinned SHA-256 certificate fingerprints.
- **Ephemeral PIN Pairing:** Pairing requires a 6-digit one-time PIN (10-minute expiry) generated by the Owner. New workstations remain in `PENDING_APPROVAL` status until explicitly authorized.
- **HMAC-SHA256 Request Signing:** Every client request includes headers `X-Device-Id`, `X-Device-Signature`, `X-Request-Timestamp`, and `X-Request-Nonce`.
- **Anti-Replay Protection:** Enforces a freshness window of $\pm 300\text{s}$ and maintains an in-memory nonce cache to reject duplicate requests.
- **Instant Revocation:** Device revocation immediately terminates client session access server-side.

### E. Cryptographic Backup & Disaster Restore Security
- **Authenticated Encryption:** Backups use AES-256-GCM authenticated encryption with 256-bit keys derived from owner passphrases via Scrypt (`N=32768, r=8, p=1`).
- **Encrypted Header:** Files start with the `MEDIDESK_ENC_V1` header containing a 16-byte random salt, 12-byte initialization vector (IV), and 16-byte GCM authentication tag.
- **Integrity Validation:** Checksums and authentication tags are verified before database replacement.
- **PRE_RESTORE_SAFETY Snapshot:** The system creates an automatic encrypted snapshot of the current active database before applying any restore.
- **Owner-Only Restore:** Restore execution is restricted exclusively to the authenticated `OWNER` role with mandatory password re-verification.

### F. Patient Privacy & DPDP Act Compliance
- **Explicit Privacy Consent:** Digital document delivery (WhatsApp, SMS, Email) strictly verifies that patient consent (`consentObtained: true`) is recorded before queuing or dispatching records.
- **Audit Logging:** Structured audit logs capture actor identity, timestamps, organization ID, and modified resource IDs across all clinical, financial, and administrative operations.
